# 视频超分

左侧入口为「超分」，内含「视频超分 / 视频超分任务 / 高级设置」。沿用现有功能卡片、文件选择、任务队列和通知体系；以东方 MMD 为主要使用场景。

## 主页面

- 输入视频支持浏览和单文件拖入；异步读取分辨率、原始分数帧率、时长和音轨。
- 目标尺寸支持 720p、1080p、1440p、2160p，2/3/4 倍，以及自定义宽高。预设按原比例计算并自动适配竖屏，尺寸对齐为偶数；自定义比例不一致时可选择补边或居中裁剪。
- 模型提供 `realesr-animevideov3`、`realesrgan-x4plus`、`realesrgan-x4plus-anime` 和 2× AniSD SPAN。默认动漫视频模型。AniSD SPAN 使用 `2x_AniSD_G6i1_SPAN_215K`，固定以原生 2 倍推理，再调整到所选输出尺寸。
- 默认开启「相同帧复用」，同一任务内完全相同的画面只进行一次超分，包含跨批次及不相邻的重复画面；主页面可关闭进行对比。预览及任务显示实际超分/复用帧数。
- 编码支持 H.264/H.265、均衡/高画质/小体积（CRF 21/18/25）、MP4/MKV；音频支持复制/AAC/移除。
- 默认另存为 `原名_SR_宽x高.格式`，拒绝覆盖已有输出。手动选择输出路径后更改参数不会覆盖该路径，扩展名需与格式一致。
- 添加任务时保存不可变参数快照，更改主页面或高级设置不会影响已添加的任务；同一输出路径去重，同一输入可创建不同尺寸的输出。

## 预览

主页面复用字幕页的视频画面与异步逐帧读取方式，通过拖动进度条选择起点，显示当前帧号与毫秒时间；当前拖到并显示的画面就是起点，不再单独填写秒数。连续拖动合并为最新定位请求，松手立即定位；当前画面未加载完成时暂时禁用预览，切换视频后回到首帧。

从选定起点处理最多 5 秒，预览和完整任务共享串行队列，防止同时抢占显存。排队中和渲染中的预览都可取消。

分析阶段单独显示检测帧数与用时，不计入超分速度。分析完成后，进度分母固定为去重后需超分的独特帧总数；已处理、剩余帧数和最近约 8 秒的超分速度均只统计独特画面，同一结果被复用多次也只计一次。关闭复用时按全部原始帧统计。超分预计剩余时间为剩余独特帧数除以近期超分速度，不包含最后的编码和合成时间；首次统计前显示估算中。原始帧数、可复用帧数另行显示，预览同时显示已复用帧数。

独特帧全部完成后显示超分完成，继续处理复用帧、编码收尾和合成输出等阶段，不显示失真的超分剩余时间；最终输出校验完成前任务总进度保持低于 100%。任务卡片将阶段/复用信息与已处理/剩余/速度分行显示。

完成后打开同步对比窗口，支持画面播放、进度拖动、上一帧/下一帧；音频可通过「用播放器打开」试听。失败时保留原因并提供重试入口。预览文件与完整输出分开，临时图片在结束或取消后清理。

## 处理链路与边界

1. 用 ffprobe 读取视频信息。无帧数的容器额外读取视频包数，避免用音轨总时长猜帧数。
2. 开启复用时，FFmpeg 顺序解码选定范围的 RGB24 像素。超分与补帧共用完整帧 SHA-256 实现，Windows 优先使用系统 SHA-256。扫描时最多四路并行计算签名，再按源帧顺序统计重复画面；高分辨率会自动减少在途帧数。渲染时用同一算法逐帧核对签名。即使只有一个像素不同，也会单独超分。
3. 渲染阶段仅启动一次连续解码，将源视频顺序读取为 RGB24 原始像素流；在内存中校验签名；默认仅为首次出现的独特画面创建 RGB24 共享帧，不将普通输入帧写成 PNG。参数默认每批 16 帧；共享内存路径按输入＋模型输出的原始像素量将单批收缩到约 128 MiB，至少一帧。不再对每批重新寻址、启动解码进程，也不再重新读取和解码 PNG 来校验。沿用原有非方形像素归一化取整规则，避免优化改变送入模型的画面。小数帧率保持分数表达；非零预览起点向前留四分之一帧，避免微秒舍入丢帧。
4. 独立的预读线程为 GPU 准备后续批次，独立的编码线程处理上一批输出。两个队列各只容纳一批，另有各阶段正在处理的批次，因此临时图片可同时包含数批；CPU 准备、GPU 超分、CPU 编码可以重叠进行，取消或任一阶段出错时会停止并回收全部后台进程，再清理临时文件。

   Windows 上连续解码的原始像素通过 64 KiB 系统管道读取，预读队列满时直接阻塞解码器，避免 Qt 的异步标准输出缓冲绕过队列限制、将长视频的后续原始帧持续积压在内存中。使用重叠 I/O 事件在数据到达时唤醒，不再每次等进程句柄 10 毫秒；单次等待最长 50 毫秒，取消时完成或取消待处理的读取后才释放像素内存。短读错误保留累计标准错误，并记录当前帧号、已读字节数及进程退出状态。回归测试使用 4000 帧的独立合成视频模拟消费端停滞，检查内存增长及取消退出；另覆盖提前结束和 852×474 像素流吞吐。
5. 只向 Real-ESRGAN ncnn Vulkan 传入未处理过的独特画面。Windows 默认官方 CLI 旁存在 `fkw-superres-worker.exe` 时，使用同一任务内常驻的模型会话：首批加载一次，后续批次只发送共享帧清单并等待完成。引擎内部划分为 1 条输入线程、最多 2 条 GPU 提交线程、3 条结果线程；预读和结果队列各最多 2 项，队列像素约 128 MiB，单帧较大时允许一个独立帧，不累计跨批次 CPU 图片。全命中缓存的批次不发推理请求。没有常驻程序、自定义 CLI 或设置 `FKW_SUPERRES_LEGACY_ENGINE=1` 时保留原 CLI 路径，便于兼容和对照；常驻程序实际失败时直接报告错误，不静默回退。动漫视频模型按目标尺寸选择 2/3/4 倍，通用/插图模型固定使用原生 4 倍，之后精确调整到目标尺寸。模型权重、预留边缘、分块策略与上游保持一致。
6. 默认用 RGB24 共享映射传递输入与模型结果。结果线程将 BGR 转为 RGB 并发布完成标记；按原帧序展开共享引用，直接通过有界标准输入流送入一个连续 FFmpeg 编码进程，再缩放/补边/裁剪。FFmpeg 写入队列最多约 256 KiB，等待期间持续响应取消及其他阶段的失败。只有未来批次仍会使用的重复帧结果才通过独立线程保存成低压缩无损 PNG；待保存像素约 64 MiB，单个大帧另计，最后一次复用后删除。缓存回读只针对这些重复结果，普通帧不进行 PNG 压缩、落盘、解码。每一帧的播放时间与原始帧数保持不变。编码后的临时视频和重复结果磁盘缓存仍会随时长及复用间隔增长；像素内存由在途批次、工作队列、模型和编码器共同决定，不把完整视频的像素保存在内存。
7. 合并片段及源音轨，统一输出 SDR BT.709；校验尺寸、帧率、可用的帧数信息和音轨后，在目标目录内改名发布结果。失败、取消及输出冲突不会留下最终半成品或覆盖旧文件。对部分 FFmpeg 发行版在拒绝覆盖时返回零退出码的情况，额外检查编码目标是否已存在及输出是否非空。

首版支持固定帧率 SDR 视频，输出 8-bit yuv420p；检测到可变帧率或 HDR 时给出转换提示。使用逐帧增强，尚不提供时序视频模型、补帧、HDR 色调映射或真人脸部修复。MMD 的模型选择应通过实际片段评估头发、衣服纹理、阴影、光影及运动稳定性。

相同帧复用限定在同一任务内，不跨模型、参数或文件混用。开启后增加一次像素签名扫描；没有完全相同画面的视频可关闭此选项以省去扫描和逐帧校验的开销。

## 资源与发布

默认读取 `tools/realesrgan/realesrgan-ncnn-vulkan.exe`、相邻 `models` 目录，以及 `tools/ffprobe.exe`。FFmpeg 使用既有配置。路径、显卡编号、分块大小、TTA 和每批缓存帧数可在高级设置中修改；未找到资源时直接说明缺少内容，不会静默使用普通缩放。

`scripts/stage-superres.ps1 -SourceTools tools -DestinationTools tools -Download` 从官方固定发行版获取引擎，核对 SHA256，并精确收录运行库、五组模型和许可证，排除演示视频及调试运行库。ffprobe 从 FFmpeg 发行包的 bin 目录提供。完整安装包及普通工具包包含超分资源；Clear 更新保持原有不携带完整工具链的策略。

在 x64 MSVC 开发环境运行 `scripts/build-superres-worker.ps1` 可构建常驻程序及 `WORKER-LICENSES.txt`，将两者放在官方 CLI 旁即可启用，发布脚本会一并收录；`-Download` 且缺少常驻程序时自动构建。依赖包固定为 ncnn 20221128、Vulkan headers 1.3.231 并校验 SHA256，复用 `downloads/interpolation` 下载缓存。上游源码版本和本地适配见 `third_party/realesrgan-ncnn-vulkan/UPSTREAM.md`。自定义引擎不会因系统其他位置存在常驻程序而被替换。

AniSD SPAN 使用支持该模型的 Windows 常驻程序。模型单独从 [Sirosky 的 AniSD 发布页](https://github.com/Sirosky/Upscale-Hub/releases/tag/AniSD) 获取。用 [pnnx 20261020](https://github.com/pnnx/pnnx/releases/tag/20261020) 执行 `pnnx 2x_AniSD_G6i1_SPAN_215K_fp32.onnx fp16=0`。将生成的 `.ncnn.param` 和 `.ncnn.bin` 放入超分模型目录，文件名分别为 `2x_AniSD_G6i1_SPAN_215K.param` 和 `2x_AniSD_G6i1_SPAN_215K.bin`。在参数文件中将完整输入节点名 `in0` 和输出节点名 `out0` 分别替换成 `data` 和 `output`。官方 ONNX 的 SHA256 为 `ec446acf6fde4a23a27625ef1102d72f41eba2c2f6a2e84a45848b986f08fedf`。

## 验证

开启 `FKW_BUILD_TESTS` 构建 `superres-tests`，普通运行验证尺寸、模型倍率、方向、分数帧率及可变帧率识别。设置 `FKW_SUPERRES_INTEGRATION=1` 后运行实际 Vulkan 引擎，覆盖中文/空格/特殊字符路径、小数帧率多批次合成、音轨、非零起点预览、取消清理、输出冲突、界面预览进度及参数快照。测试使用独立的临时用户目录。

可选 `FKW_SUPERRES_CAPTURE_DIR` 保存实际主页面、预览渲染、对比、任务、高级设置截图。

重复帧集成用例使用 18 帧无损视频，包含跨批次停格、不相邻重复画面及一个像素的微小改动。开启复用时仅推理 4 帧，复用 14 帧，并跳过全命中批次的引擎启动；与关闭复用的结果逐帧校验相同，同时检查帧率、时长、音轨及缓存清理。

速度计使用单调时间和最近窗口，单测覆盖长时间分析不稀释渲染速度及停滞时速度归零。集成测试使用日志中的毫秒区间确认预读提前完成、编码与下一批推理重叠，并注入编码冲突检查失败退出及缓存清理。

性能验证使用 5 秒短片，不运行整部视频；可选 `benchmarkMmdSample` 通过 `FKW_SUPERRES_BENCHMARK_VIDEO / DIR / LABEL` 指定素材、输出目录及结果名。2026-11-17 同一 MMD 片段（151 帧、108 个独特画面、1946×1080 输出），从有界解码修复版的 22.7 秒降至事件唤醒＋常驻模型版的 15.8 秒，耗时约减少 31%；全部 RGB 逐帧哈希一致。首批预读从 3108 毫秒降至 188 毫秒，后续预读约 0.2～0.4 秒，日志仅出现一次模型会话启动。数字仅代表该短片及当时硬件状态，长视频最终速度仍受画面、编码、磁盘及其他程序负载影响；开始前的签名扫描仍有开销。

可选 `benchmarkMmdSample` 用例通过 `FKW_SUPERRES_BENCHMARK_VIDEO`、`FKW_SUPERRES_BENCHMARK_DIR`、`FKW_SUPERRES_BENCHMARK_LABEL` 指定片源和结果位置，默认运行开头的 5 秒。`FKW_SUPERRES_BENCHMARK_START`（秒）、`FKW_SUPERRES_BENCHMARK_FRAMES` 和 `FKW_SUPERRES_BENCHMARK_MODEL` 可指定起点、帧数和模型。用例记录总耗时与输出参数。

## 共享帧版本的验证与对照

`cpp/video_frames` 定义共享 RGB24 头部、映射生命周期及独立的读图/推理/结果队列；超分和补帧共用。保留 `FKW_VIDEO_PNG_TRANSPORT=1` 以使用图片兼容路径。PNG 备用输出改用固定低压缩级别、无自适应过滤的 stb 无损编码；它与共享帧的模型输出逐像素一致。共享帧只在数据完整后发布，跨进程消费者持有映射，最后一个引用释放后系统回收；取消及任一阶段失败会关闭管道、停止工作进程和线程，再删除临时目录。

同一素材开头 5 秒（151 帧、108 独特画面、1946×1080 输出），常驻模型＋WIC 图片路径复测 16.039 秒，共享帧＋连续编码 9.494 秒，耗时减少 40.8%。一轮多个阶段同时停顿约一分钟的异常基准不用于计算。普通验证涵盖共享映射生命周期、批次预算、超分 2/3/4 倍及 TTA 的 PNG/内存原始像素一致、长停滞解码背压、复用、取消、编码失败、预览及参数快照。

连续编码不再按每批重置编码器，GOP 结构和视频文件字节会变化。验证要求模型输出像素一致、编码质量参数保持、帧数/帧率/时长/音轨正确；不要求新旧有损编码视频的解码像素或文件哈希相同。短片数字仅代表当时环境，不保证整片同幅加速。
