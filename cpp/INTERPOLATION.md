# 视频补帧

左侧入口为「补帧」，包含「视频补帧 / 视频补帧任务 / 高级设置」，沿用超分的文件卡片、任务队列、画面拖动预览与通知。主要用于东方 MMD。

## 使用

- 主页面选择视频、输出路径和目标帧率。支持 60、59.94、120、119.88、50、30 fps，按原始分数帧率提高 2/3/4 倍，或自定义整数帧率。目标必须高于原片，最高 240 fps、原帧率的 16 倍。
- 默认 RIFE 4.6，可切换 RIFE 4.0 对比。支持 H.264/H.265、均衡/高画质/小体积、MP4/MKV、音频复制/AAC/无音频。保持画面比例和时长；非方形像素与旋转会归一化为显示方向、方形像素和偶数尺寸。
- 默认启用静止画面复用和切镜保护。仅在两端完整 RGB 像素完全一致时复用，保留原作的定格节奏。相邻帧的采样颜色差异达到阈值（默认 30%）后，程序在缩略图上匹配不同区域的纹理。如果足够多的区域在移动后仍能对上，就继续补帧，否则保持前一镜头的原帧。建议用预览检查快速运镜、舞台闪光和真实切镜处的效果。
- 拖动画面进度条，当前显示帧就是预览起点，处理最多 5 秒。预览与本功能完整任务共用串行队列；补帧和超分还共用可取消的显卡租用锁，避免同时加载模型抢占显存。
- 预览结果按同一播放时间映射原片和补帧视频，不按相同帧号比较；支持播放、拖动、上一帧/下一帧和外部播放器试听。

## 时间与进度

对输出帧索引 `j`，其源时间位置为 `j * 源帧率 / 目标帧率`，使用左右原始帧和该位置的小数部分推理。计算位置使用全局输出帧索引，批次边界不重置时间。CFR 文件的平均帧率与标称分数帧率相差不超过 0.0001 fps 时，以标称值为准，避免尾包时长舍入使原始时刻被误作新帧推理。原始时刻直接使用原片；静止区间直接复用；检测到切镜时保持左侧原帧，直到新镜头的原始时刻。尾部不足一个原始帧周期时保持最后一帧。输出帧数为 `ceil(选定原始帧数 * 目标帧率 / 原始帧率)`，视频时长误差至多约一帧；不通过改变播放速度补帧。

有些超分文件把略有舍入的平均帧率也写进了标称帧率。补帧读取到确切帧数后，如果固定帧率与常用整数或 NTSC 分数帧率相差至多 0.0001 fps，且校正前后的整片时长相差至多 1 毫秒，就按该标准帧率对齐。比如 6,065 帧的 30.000099 fps 素材转 60 fps，每个源帧会出现在对应的偶数输出帧（从 0 计数）。日志中的 `direct` 包含直接输出的源帧和片尾保持帧。

预览在所选范围末尾保留一个额外源帧作前瞻，避免在片段末尾人为制造停顿；额外帧不延长预览时长。FFmpeg 预览定位向前留四分之一帧，避免小数时间舍入导致漏首帧。

分析阶段以 CPU 解码，与最多四路完整像素 SHA-256 及切镜检测并行。Windows 优先使用系统 SHA-256 实现。图像越大，同时分析的帧数越少，结果按源帧顺序汇总。任务日志中的 `[analysis]` 记录扫描帧数与实际耗时。

扫描结束后固定需模型计算的新帧总数。已处理/剩余、百分比、最近约 8 秒速度和补帧预计剩余时间均以这些帧为准。全部可直接复用时跳过 GPU 与模型加载。编码收尾、合成与校验单独显示，发布完成才到 100%。剩余时间只估算补帧计算部分。

## 执行与资源

`fkw-rife-bridge` 封装官方 RIFE/ncnn 推理代码：一项任务仅加载一次模型，通过 UTF-8 行协议接收显式帧对、时间点与输出路径；不逐帧、逐批重启引擎。输入线程缓存当前帧对，并通过有界队列预读；GPU 推理保留单路，3 条独立结果线程负责发布 RGB24 或快速无损 PNG，保存结果期间可以继续进行下一次推理。主程序的独立预读与编码线程分别准备后续批次、编码上一批，每个队列容量一批；临时图像同时保留的批次数有界，片段编码后删除。临时编码片段会随视频时长增长。分析仅保存签名和时间计划，不把整部视频解成图片。

默认通过 RGB24 共享内存传递帧对和结果，普通输入及结果不写 PNG；原帧、静止保持和切镜保持直接引用已有内存帧。结果按全局输出帧号恢复顺序，通过有界管道送入一个连续 FFmpeg 编码器。原始像素连续读取，默认单批 16 个原始帧并携带一个前瞻帧；共享内存路径根据输入分辨率及输出倍率自动将批次收缩到约 128 MiB，至少一帧。再次解码时核对分析签名，避免帧序偏差导致复用错误画面。只有完整写入一张新图，引擎才确认一帧完成；每批验证帧数。任一阶段失败或取消会停止引擎、解码与编码，等待线程释放文件后清理缓存。最终视频在输出目录的临时目录内合成，校验尺寸、帧率、可用帧数、时长及音轨，使用拒绝覆盖的改名保存；失败、重试和路径冲突不覆盖已有文件。

当前支持固定帧率 SDR，输出 8-bit yuv420p；VFR/HDR 给出转换提示。模型不能保证恢复所有动作细节，长定格和快速运动可能仍有失真，应通过实际 MMD 片段确认。

默认资源位置：`tools/rife/fkw-rife-bridge.exe`、`tools/rife/models/rife-v4.6`、`tools/rife/models/rife-v4`。FFmpeg 沿用已有设置；引擎、模型、ffprobe、缓存、显卡编号、单批帧数、UHD、空间/时间 TTA、切镜阈值可在高级设置调整。

`scripts/build-rife-bridge.ps1` 在 x64 MSVC 环境构建桥接程序，使用固定 SHA256 的 ncnn 20221128 SDK、Vulkan Headers 1.3.231 和 Vulkan Loader 导出表。未修改的 RIFE 推理/着色器代码固定于 `a7532fc3f9f8f008cd6eecd6f2ffe2a9698e0cf7`，见 `third_party/rife-ncnn-vulkan/UPSTREAM.md`。桥接程序与模型仅使用 Vulkan，不要求用户安装 CUDA/PyTorch。

`scripts/stage-interpolation.ps1 -SourceTools tools -DestinationTools tools -Download` 核对官方 20221029 模型发行包 SHA256，仅提取两组模型、运行库及许可证，构建并收录桥接程序。普通工具包及完整安装包收录，Clear 更新继续保持不带完整工具链的策略。CI 按引擎源码及构建脚本的内容缓存资源。

## 短测试

开启 `FKW_BUILD_TESTS` 构建 `interpolation-tests`。普通测试验证分数帧率、非整数倍率全局时间点、静止与切镜计划、预览末尾前瞻。`FKW_INTERPOLATION_INTEGRATION=1` 后可单独运行实际渲染、音轨/时长/尺寸、跨批次单次模型加载、非零起点预览、静止和切镜无 GPU 路径、运行中与等待显卡时取消、编码错误、路径冲突、UI 预览时间映射、参数快照及排队取消。测试使用临时用户目录，不改实际用户设置。

可选 `mmdShortPreview` 通过 `FKW_INTERPOLATION_MMD` 和 `FKW_INTERPOLATION_OUTPUT` 指定实际 MMD 与测试目录，只处理 2 秒。测试超时为 60 秒，不运行整部视频。

## 性能与内存通道

补帧和超分共用 `VideoRawDecoder`、`MemoryFrame`、`VideoRawEncoder` 以及引擎读图/推理/结果队列。Windows 解码使用 64 KiB 事件唤醒系统管道形成背压，避免 Qt 异步标准输出绕过预读队列，将剩余原始视频持续缓存到内存。后续阶段失败也能中止解码读取，取消后等待待处理 I/O 回收。FFmpeg 编码写入队列约 256 KiB；引擎队列各至多两项、约 128 MiB（超预算单帧单独处理）。整体峰值还包含若干在途批次、模型和 FFmpeg，不随视频长度累计完整像素历史。

保留 `FKW_VIDEO_PNG_TRANSPORT=1` 进行兼容对照；图片输出使用低压缩级别、固定过滤的 stb 无损编码。只有结果完整保存或发布后才发出 DONE，一批全部完成后才发 BATCH_DONE。共享帧直接测试与 PNG 路径的补帧模型输出逐像素一致，并验证原帧/保持/切镜和前瞻的顺序及音画时长。另有 4000 帧合成视频的暂停消费测试，验证内存不积压和后续阶段失败时及时退出。

同一实际 MMD 在 442.73 秒处取 2 秒、输出 60 fps：旧常驻 RIFE＋WIC 图片路径 4.029 秒，共享帧＋连续编码 2.932 秒，减少 27.2%。连续编码改变分段/GOP 结构，因此不要求新旧 MP4 字节一致；保持模型像素、质量参数、帧序、帧数、帧率和音轨正确。数字只代表该短片及当时环境，不保证整片同幅加速。
